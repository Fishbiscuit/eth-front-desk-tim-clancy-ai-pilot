# ETH Front Desk Pilot — Source Ledger

This is a research lead list for the pilot. It does not claim that each source has been independently verified in this project. Before external circulation, record access date, version, exact claim, and limitations.

| ID | Source lead | Intended use | Status |
|---|---|---|---|
| S1 | Ethereum Foundation CROPS / mandate material, March 2026 | Starting reference for self-sovereignty, censorship resistance, open source/freedom, privacy, and security | Verify exact canonical URL and scope |
| S2 | [Constitutional AI](https://arxiv.org/abs/2212.08073) | Principle-guided critique and revision precedent | Verify methods and limits |
| S3 | [LoRA](https://arxiv.org/abs/2106.09685) | Parameter-efficient adaptation precedent | Verify implementation assumptions |
| S4 | [Direct Preference Optimization](https://arxiv.org/abs/2305.18290) | Preference-learning candidate | Verify applicability and evaluation limits |
| S5 | [Retrieval-Augmented Generation](https://arxiv.org/abs/2005.11401) | Evidence-retrieval foundation | Verify current implementation choices |
| S6 | [Hugging Face TRL](https://huggingface.co/docs/trl) and [PEFT](https://huggingface.co/docs/peft) | Candidate training tooling | Pin versions before experiments |
| S7 | [EIP-1](https://eips.ethereum.org/EIPS/eip-1) | EIP status and process distinctions | Verify against current process |
| S8 | [OWASP prompt injection guidance](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) | Treat retrieved content as untrusted | Verify current guidance |
| S9 | Ethereum protocol specifications, EIPs, client documentation, and project technical documentation | Current evidence for architecture reviews | Build bounded source catalog |
| S10 | Security disclosures and selected research discussions | Failure modes, incidents, and disagreement | Rights and relevance review required |

## Source rules

- A project’s own documentation is evidence of what it claims, not independent proof that the claim is true.
- Publication or proposal status is not equivalent to deployment or adoption.
- Preserve published, updated, retrieved, network/version, status, hash, rights, and conflict metadata where available.
- Separate frozen-evidence evaluation from current-evidence evaluation.
- Do not ingest private correspondence, unreleased reports, or user-submitted architecture documents without explicit clearance and consent.
